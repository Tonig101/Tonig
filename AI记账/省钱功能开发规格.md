# 省钱功能开发规格（v1 · 省钱图谱）

> 目标：把《大学生全网省钱与防割韭菜图谱（100 条）》从「一段读得爽的文本」变成「可计算、可打卡、可复盘的产品模块」，
> 并接进现有 `AI记账` 的账本 / 省钱雷达 / 理财教练三条链路。
> 前提约束：**零依赖、零构建、`file://` 双击可跑、断网可演示**（与现有项目一致）。

## 1. 现状盘点：已经有什么、缺什么

| 现有能力 | 位置 | 覆盖 | 缺口（本次要补的） |
| --- | --- | --- | --- |
| 商家活动日历（肯德基周四、麦当劳周一…） | `deals.js` `MERCHANTS`（8 点位） | 只有 8 家、只有「哪天有活动」 | 没有「怎么点才省」（如：萨莉亚避开牛排点意面） |
| 比价口径引擎（到手价 / 折单价 / 可比性） | `deals.js` `compareOffers` | 用户抄价后的换算 | 图谱 100 条里绝大多数是「固定打法」，不需要比价，只需要**动作指令** |
| 校园平替词典（21 条） | `data.js` `ALTERNATIVES` | 记账后命中品牌才弹 | 只在「已经花完了」才出现，属于事后；图谱要**事前** |
| 理财教练省钱问答（5 条固定话术） | `coach.js` `showSaveMoneyGuide` | 5 条泛泛建议 | 没有分类、没有检索、没有量化、没有打卡 |
| 冷静期 / 累计省下金额 | `app.js` `savedMoney` / `blockedCount` | 只管「没买成的」 | 没有「买成了但买对了」的省钱账 |

**一句话**：现有省钱能力是「日历 + 比价 + 事后平替」，缺一个**事前可执行的动作库 + 可量化的省钱账**。

## 3. 数据结构

### 3.1 条目 schema（`savings_data.js`）

```js
{
  id: 'fastfood.mcd.01',            // 分类.关键词.序号，全局唯一，打卡记录以 id 为键，永不改
  cat: 'fastfood',                  // 10 个分类 key，见 §3.2
  title: '麦当劳周一随心配 1+1',
  action: '周一点「随心配 1+1」13.9 元，饮料换中杯不换大杯。',   // 五要素①：具体做法
  who: '想省钱又想吃快餐的人',        // 五要素②：适用人群
  gate: '需周一到店 / 小程序领券',     // 五要素③：门槛
  scene: 'weekday-lunch',            // 五要素④：场景 key（用于筛选，不直接展示）
  risk: '仅周一有效；部分门店不参加；换大杯差价不划算',  // 五要素⑤：弊端，必填
  trigger: { weekday: [1] },         // null | {weekday} | {monthday} | {timeRange}
  save: { type: 'fixed', amount: 6.1 },
  priceRef: { before: 20.0, after: 13.9 },   // 可空对象 {}，ratio 型必填 before
  billCats: ['餐饮'],                 // 关联账本分类，取值必须 ∈ CATEGORIES 的 9 个 key
  keywords: ['麦当劳', '随心配', '1+1'],
  certainty: 'stable',               // stable 规律稳定 | varies 档期/力度常变 | local 以你学校为准
  source: '麦当劳 App / 门店'
}
```

**`save` 四型**（决定能不能量化、怎么量化）：

| type | 字段 | 含义 | 例子 |
| --- | --- | --- | --- |
| `fixed` | `amount` | 每次固定省多少 | 淘宝代金券省 3 元 |
| `ratio` | `rate` + `cap`，需 `priceRef.before` | 按原价打折 | 零食店 88 折 → rate 0.12 |
| `range` | `min` / `max` | 只能说区间 | 平台差价 5-15 元 |
| `none` | — | 无法量化（长期习惯型） | 保温杯大法、图书馆免费资源 |

**`save.once` + `save.onceLabel`（实现阶段新增，解决「总额霸榜」）**

有些条目的金额是**一次性总额**，不是「今天能省多少」：双 11（省 300 是整场大促）、年卡（省 400 是一年）、驾校 / 培训班（省的是总价）。
这类必须打 `once: true`，并给一个 4-6 字的标签（`onceLabel`），否则今日清单会被它们霸占、文案也会骗人：

| 条目 | save | 卡片文案 |
| --- | --- | --- |
| 双 11 | `{type:'range',min:100,max:500,once:true,onceLabel:'大促可省'}` | 大促可省 ¥100.00-500.00 |
| 学校免费健身房 | `{type:'range',min:200,max:600,once:true,onceLabel:'全年可省'}` | 全年可省 ¥200.00-600.00 |
| 报培训班前先看免费课 | `{type:'range',min:200,max:2000,once:true,onceLabel:'一次性省'}` | 一次性省 ¥200.00-2000.00 |

规则：**`once` 条目在 `rankToday` 里不按金额参与排序（按 -1 处理），但照常可以被推荐**（双 11 预热期本来该出现）。

**`certainty` 三档**（决定 UI 语气，直接对应「绝不编造价格」红线）：

| 值 | UI 标记 | 用途 |
| --- | --- | --- |
| `stable` | 无标记 | 规律确定（每周二 9.9） |
| `varies` | 灰标「力度常变」 | 档期型（会员日 88 折、满减凑单） |
| `local` | 黄标「以你学校为准」 | 依赖具体校区（教师食堂、南城香、某家打印店） |

### 3.3 打卡状态（独立 storage，**不并入主账本**）

```js
// localStorage key: 'ai_jizhang_savings_v1'
{
  version: 1,
  logs: [
    { id: 'fastfood.mcd.01', date: '2026-10-26', saved: 6.1, manual: false, at: 1750000000000 }
  ]
}
```

**为什么独立 key**：主账本 `ai_jizhang_v1` 已经承载预算 / 目标 / 成就，`normalizeState()` 一旦改动要重新回归 720 组周期用例；
打卡属于可选功能，损坏时**只重置自己，不能连累账本**。

### 3.4 与现有字段的关系（互不覆盖）

| 指标 | 字段 | 语义 |
| --- | --- | --- |
| 冷静期拦下的钱 | `state.savedMoney`（已有） | 「**没买成**」省下的 |
| 图谱打卡省下的钱 | `savings.logs[].saved` 汇总 | 「**买对了**」省下的 |
| 成就条展示 | 两个数**分开显示** `拦下 ¥X · 买对省 ¥Y` | 绝不合并，否则用户会以为冷静期省了两次 |

## 4. 计算逻辑

### 4.1 `estimateSave(entry, ctx)` — 可省金额估算

```
fixed  → round2(amount)
ratio  → priceRef.before 缺失 ? null : round2(min(before × rate, cap ?? Infinity))
range  → round2((min + max) / 2)
none   → null
```

- 返回 `null` 表示「省多少看用量」，**不参与累计**，UI 显示「省多少看用量」，绝不填 0（填 0 会让用户以为这条没用）。
- `round2 = Math.round(n * 100) / 100`，精度统一 2 位，与 `deals.js` 一致。

### 4.2 `matchTrigger(entry, now)` — 今日是否可用

| trigger | 命中条件 | 边界 |
| --- | --- | --- |
| `null` | 恒命中（常驻动作） | 今日清单里只做**填充**，最多 3 条 |
| `{weekday:[1..7]}` | `isoWeekday(now) ∈ 数组`（1=周一，与 `deals.js` 一致） | — |
| `{monthday:[1..28]}` | `now.getDate() ∈ 数组` | 数据校验强制 ≤28，规避 2 月缺日 |
| `{timeRange:['20:00','23:00']}` | 当前 `HH:mm` 落在区间内 | **跨零点**（`20:00-02:00`）拆成 `>=20:00` 或 `<=02:00` 两段判断 |
| `{mmdd:['11-11']}` | 月日相同 | 双 11 / 双 12 这类固定日期（**实现时新增**，原规格只列了前三种） |
| `{window:[{from:'10-20',to:'11-11'}]}` | 月日落在区间内 | 大促预热 / 开学季；`from > to` 视为跨年 |

多维度同时声明时 **任一维度满足即命中（OR）**——例如麦当劳同时挂「周一」与「每月 8/18/28 会员日」。

全部用**本地时间** `new Date()`，不用 UTC；`dateKey` 与 `AJ.deals.dateKey()` 同语义（YYYY-MM-DD 零填充，实现上本地各写一份，避免 Node 单测要跨文件 require）。

### 4.3 `rankToday(entries, ctx)` — 今日清单排序（必须稳定可复现）

```
第一步（硬规则，先于排序）
  有 trigger 但今天不命中  → 直接排除，不参与打分
  当天已打卡                → 直接排除
第二步打分
  + 40   trigger 命中今天
  + 25   entry.billCats ∩ [本周期支出 Top1 分类] ≠ ∅
  + 20   entry.billCats 本周期有支出（> 0）
  + 15   budgetState.status ∈ {danger, tight}（越紧越先给）
  + 10   certainty === 'stable'
  + 5    estimateSave > 0 且不是大促 once 型
第三步取数
  先取「命中今天」的（score DESC → est DESC → id ASC）
  再用常驻条填充，最多 3 条
排序：score DESC → sortEst DESC（null 与 once 均视为 -1）→ id 字典序 ASC
```

两条硬规则都是在实现阶段补的，原因很直接：

- **「今天用不了的不许进清单」**：否则周一给用户推「周四肯德基」，清单第一句就在骗人；
- **大促条目（`save.once: true`）不按总额参与排序**：双 11 的「省 300」是整场活动的总额，不是「今天能省 300」，拿它加榜会把所有日常动作挤掉。这类条目的文案也必须写成「大促可省 ¥100-500」而不是「≈ 省 ¥300」。

最后一级 `id` 字典序是为了**同分可复现**——同一个日期渲染两次必须顺序完全一致，否则验收无法通过（§8 C7）。

### 4.4 累计省钱账口径

```
monthSaved = Σ logs.where(date ∈ 当前预算周期).saved     // 周期口径，跟着 budget.cycleStart 走
totalSaved = Σ logs.saved                               // 累计，不随周期清零
```

- 打卡时若用户填了实际省额 → 用实际值（`manual: true`）；未填 → 用 `estimateSave`，为 `null` 则记 `saved: 0` 但**计入条数**。
- 成就条文案：`买对省 ¥{totalSaved}（{logs.length} 条）`，金额 0 时只显示条数。

### 4.5 幂等规则（防重复记账）

```
打卡：若 logs 中已存在 {id, date=今天} → 视为取消，删除该条，金额回滚
    否则 → push 一条
```

同一个 id 同一自然日只允许一条，第二次点击必须是「取消」而不是「再省一次」。

## 6. 边界情况与异常处理

### 6.1 数据边界

| # | 情况 | 处理 |
| --- | --- | --- |
| 1 | 条目缺 `risk` / `source` / `action` | `validate()` 报错并列出 id；渲染时跳过该条（**不渲染半截卡**），控制台 `console.warn` |
| 2 | `monthday` 写了 29/30/31 | 校验直接拒绝（限 1-28），避免 2 月缺日 |
| 3 | `billCats` 含不存在分类 | 校验拒绝，取值域 = `CATEGORIES` 的 9 个 key + `'跨类'` |
| 4 | `ratio` 型缺 `priceRef.before` | `estimateSave` 返回 `null`，不抛错 |
| 5 | 关键词跨条目重复 | 取 `cat` 权重高者；仍相同按 id 序取第一条，**一次提问只弹一张卡** |
| 6 | 与 `ALTERNATIVES` 重叠（星巴克 → 瑞幸） | P0 阶段不合并；P1 用 `aliasOf` 指向平替 id，累计时只算一次 |

| 8 | 金额 > 500 元 | 卡片加底注「大额，先确认是不是一次性支出」，避免把「买电脑省 300」算进日常省钱 |

| 原文形态 | 转换规则 | 例子 |
| --- | --- | --- |
| 带「周几」 | → `trigger.weekday` | 「周二会员日买一送一」→ `weekday:[2]` |
| 带「每月几号」 | → `trigger.monthday`（限 1-28） | 「逢 8 号 88 折」→ `monthday:[8,18,28]` |
| 带「晚 8 点后」「9 点后收摊」 | → `trigger.timeRange` | 「晚 8 点后熟食半价」→ `['20:00','23:00']` |
| 带明确差价 | → `save.type='fixed'` | 「比外卖便宜 15 元」→ `fixed 15` |
| 带折扣率 | → `save.type='ratio'` | 「88 折」→ `rate:0.12` |
| 只说「便宜 30%」但无基数 | → `save.type='range'` | 「便宜 30% 以上」→ `range {min:5,max:20}` |
| 纯习惯型（保温杯、图书馆） | → `save.type='none'` + 长周期说明 | 「一年省出一部手机」→ `none` |
| 依赖具体学校 / 门店 | → `certainty:'local'` | 「教师食堂」「南城香」 |
| 力度常变 / 平台活动 | → `certainty:'varies'` | 「百亿补贴」「满减凑单」 |
| 涉及账号共享 / 二手交易 | → `risk` 必写风险提示 | 「淘宝买知网账号」 |

**不可量化也要入库**：`save.type='none'` 的条目照样显示、照样可打卡（计入条数），只是不进金额累计——
这比直接砍掉更诚实，也避免用户觉得「图谱只有降价信息」。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 100 条数据录入出错 | 统计偏差 | `validate()` + Node 单测强制守门，CI 式跑 `_test_savings.js` |
| 条目太多用户不看 | 功能沦为摆设 | 「今日清单」只给 3-5 条 + 顶部按用户实际支出分类定向，不铺 100 条 |
| 与「省钱雷达」职责重叠 | 用户困惑 | 面板顶部一句话分工：**雷达 = 哪天有活动 / 谁更便宜；图谱 = 具体怎么操作才省** |
| 价格类条目过时 | 误导 | `certainty:'varies'` + 「力度常变」标记 + 「数据说明」声明时效 |
| 打卡金额被当真实收益 | 成就感虚高 | 口径声明：金额是**估算**，以「省了多少次」为主指标 |
