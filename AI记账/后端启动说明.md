# AI 校园记账管家 · 后端启动说明

本项目把「前端页面」和「后端接口」打包在一个 Python 文件里，做到**一键启动**。

## 它做了什么

- `server.py` 同时托管：
  - 前端静态页面（`index.html` + `*.js` / `*.css`）
  - 三个接口：
    - `POST /api/health` —— 健康检查
    - `POST /api/chat` —— 接收聊天文字 → 调大模型 → 返回 `{reply, actions}`
    - `POST /api/ocr` —— 接收图片 base64 → 服务端调腾讯云 OCR → 返回 `{text}`
- 前端 `app.js` 已改造：发送消息不再写死本地回复，而是 `fetch('/api/chat')` 请求后端；
  后端不可用时自动回退到原有本地逻辑（开箱即用）。
- `ocr.js` 已改造：开启后端 OCR 后，截屏识别走 `/api/ocr`（服务端签名，密钥不进浏览器）。

## 启动步骤

1. 安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

2. 复制环境变量模板并填写密钥：

   ```bash
   cp .env.example .env
   ```

   用编辑器打开 `.env`，至少填 `LLM_API_KEY`（对话必需）。
   想用截屏识别再填 `TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY`。

3. 一键启动：

   ```bash
   python server.py
   ```

4. 浏览器打开 <http://127.0.0.1:8000>

## 未配置密钥会怎样（设计如此，不是 bug）

| 场景 | 表现 |
| --- | --- |
| 没填 `LLM_API_KEY` | `/api/chat` 返回 `fallback:true`，前端自动用本地记账逻辑 |
| 没填腾讯云密钥、但填了 `LLM_API_KEY` | `/api/ocr` 自动走「视觉大模型识别」（复用同一把密钥） |
| 腾讯云密钥和 `LLM_API_KEY` 都没填 | `/api/ocr` 返回 `error`，前端提示并保留示例小票 / 手动录入 |
| 两者都没填 | 页面正常工作，只是不走云端智能 |

也就是说：**不填任何密钥也能跑**，只是没有大模型加持；**只要配了 `LLM_API_KEY`，截图识别就自动可用**，无需再单独申请腾讯云账号。

## 环境变量一览

| 变量 | 说明 | 必填 |
| --- | --- | --- |
| `LLM_BASE_URL` | 大模型接口地址（OpenAI 兼容） | 否，默认官方 |
| `LLM_API_KEY` | 大模型 API Key | 想用智能对话 / 视觉识别则必填 |
| `LLM_MODEL` | 模型名，截屏识别需为**支持图片的视觉模型**（如 `gpt-4o-mini`） | 否，默认 `gpt-4o-mini` |
| `LLM_TIMEOUT` | 请求超时（秒） | 否，默认 30 |
| `TENCENT_SECRET_ID` | 腾讯云 SecretId | 想用腾讯云 OCR（更便宜、更准）则填 |
| `TENCENT_SECRET_KEY` | 腾讯云 SecretKey | 同上 |
| `TENCENT_REGION` | 地域 | 否，默认 `ap-guangzhou` |
| `OCR_METHOD` | 截图识别方式：`auto`(默认，腾讯云优先后退回视觉模型) / `tencent` / `vision` | 否 |
| `PORT` | 服务端口 | 否，默认 8000 |

`POST /api/capabilities` 会返回 `{chat, ocr}`，让前端弹窗准确显示当前后端识别能力（如 `ocr:"vision"`）。

## 关于「截屏识别账单」

截图里往往只有商户名、金额、偶尔有日期，**稳定提取「分类 / 消费动机」很困难**，
因此后端 OCR 只负责把图片里的文字原样识别出来（腾讯云或视觉大模型二选一）；
真正的记账结构化解析（金额、商户、分类）仍由前端本地逻辑处理，并保留「示例小票 / 手动录入」兜底。
请不要把截图识别当作 100% 准确的自动记账。
