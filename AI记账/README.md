# AI 校园记账管家 · 月末防吃土

> 一句话记账 + 周期预算引擎 + 校园平替 + 冲动消费冷静期
> 纯前端、零依赖、零构建，**双击 `AI记账.html` 就能跑**（断网可演示）。

---

## 一、如何运行

| 方式 | 操作 |
| --- | --- |
| 演示（推荐） | 直接双击 `AI记账.html`，用 `file://` 打开 |
| 本地服务器 | 可选，`python -m http.server` 后用 `http://localhost:8000` 打开 |
| 单元测试 | `node -e "require('./nlp.js'); require('./engine.js'); require('./analysis.js'); require('./ocr.js'); require('./coach.js'); require('./deals.js'); require('./savings_data.js'); require('./savings.js')"` |
| 纯 Node 断言（无需依赖） | `node _test_savings.js`（64 项）· `node _test_savings_ui.js`（103 项，从 `app.js` 切真实代码进 vm 沙箱） |
| 需要 jsdom 的测试 | `npm install --no-save jsdom && node _test_coach.js`（52 项，含简洁版教练可达 + 返回导航回归） |
| 历史快照（不纳入必跑） | `_qa_verify_coach.js` 是「简洁版教练打不开」那次修复的独立复核脚本，断言写死了改造前的视图名（`chat/coach/dash`），而现行简洁版映射到 `sai/scoach/sbudget`。**保留作为过程证据，不作为回归门槛**；同类回归已由 `_test_coach.js` §11 用现行视图名覆盖。 |

> **为什么不用框架**：评审现场可能没有网络。本项目不使用 npm、不使用打包器、不引用任何 CDN，
> 所有图表（环形进度、甜甜圈、柱状图）都是手写 SVG。

> **为什么不用 ES Module**：`file://` 协议下浏览器会以 CORS 为由拦截 `import`。
> 因此全部采用传统 `<script src>` 顺序加载 + 全局命名空间 `window.AJ`，
> 同时每个逻辑文件末尾保留 UMD 兼容尾，可在 Node 里直接 `require` 做单测。

## 三、功能说明

> 注：本文档用 `🛒` `💡` `💰` 等 emoji 作**语义标签**方便阅读；实际界面已统一为内联 SVG 线性图标（`#i-radar` / `#i-bulb` / `#i-wallet`），页面上不再显示 emoji。

### 1. 对话式自然语言记账

微信风格聊天窗，AI 气泡在左、用户在右，回车发送。

**一句话多笔自动拆分**：

```
今天中午吃黄焖鸡花了18，晚上和舍友AA聚餐付了50
  → 餐饮 / 午饭 / ¥18.00 / 备注「黄焖鸡」/ 2025-06-18
  → 社交 / 聚餐 / ¥50.00 / 备注「和舍友AA聚餐」/ 2025-06-18
```

解析规则（`nlp.js`）：

| 能力 | 说明 |
| --- | --- |
| 分句 | 按 `，。；、,!?！？~` 与「还有/然后/另外/加上/以及/顺便」切分；无金额的分句合并到相邻分句 |
| 金额 | `18` `18.5` `¥18` `18元` `18块` `花了18` `付了50`；中文数字 `十八` `五十` `两百` `一百二`(120) `三十五` |
| 多金额配对 | 「打车 15 和奶茶 12」按出现顺序切段，一段一笔 |
| 时间 | 今天/昨天/前天/今早/昨晚… → `YYYY-MM-DD`；无时间词时**继承上一笔的日期** |
| 餐段 | 早上/中午/下午/晚上/夜宵；无关键词时按当前钟点推断（<10 早餐，11-14 午餐，17-21 晚餐） |
| 分类 | 9 类关键词打分：`最长命中词长度 × 10 + 命中词数`，平手按分类表顺序 |
| 动机 | 命中情绪词 → `情绪`，否则 `刚需`；服装鞋包/数码/美妆 → `want: true` |
| 收入 | 生活费/到账/兼职/工资/奖学金/助学金/家里打/退款/收到红包 → `type: 'income'`，不计入支出 |
| 备注 | 剔除金额、时间词、动词量词后的剩余文本；为空时用分类名兜底 |

中文数字误判防护：数字后跟量词（`一双鞋`）或前无动词且不在句末（`三食堂`）时不算金额。

解析失败（无金额）时 AI 回「我没听清金额，换个说法？比如「午饭食堂 15」」并提供 3 个示例按钮。

### 2. 「月末防吃土」周期预算引擎

**按发钱日算周期，不是自然月**。发钱日设为 15 号时，周期就是 15 号到次月 14 号。

- `getCycle(today, payday, cycleLen)` → `{start, end, totalDays, passedDays, remainingDays}`
- `getBudgetState({total, spent, remainingDays, todaySpent})` → `{remaining, dailyAllowance, isOver, overBy, todayRemain, status}`
- `simulatePurchase({amount, state, remainingDays})` → `{newDaily, noodleDays, verdict, message}`

状态分级：日均 < ¥20 → `danger`；< ¥40 → `tight`；否则 `safe`。

购买模拟示例（剩 ¥450 / 9 天，买 ¥400）：

> 买完这笔，接下来 9 天日均只剩 ¥5.6。真买的话大概要 6 天泡面配食堂免费汤🥲

（`noodleDays = ceil((15 - newDaily) / 15 × remainingDays)`）

设置抽屉可改「每月生活费 / 每月发钱日 / 单笔冷静期阈值」，改完立即重算。

### 4. 冲动消费「冷静期」拦截

触发条件：`type === 'expense'` 且（`motivation === '情绪'` 或 `want === true`）且 `amount >= 冷静期阈值`（默认 ¥50）。

命中时**不直接入账**，弹出警示卡：

> ⚠️ 这笔 ¥99.00 的「娱乐 · 游戏皮肤」占你本周期生活费的 5.0%，已超过单笔 ¥50.00 的冷静线。建议先放进购物车，冷静 24 小时。
> 📉 买完这笔，接下来 13 天日均只剩 ¥38.5……
>
> **[坚持购买]** **[算了，不买了]**

- 坚持购买 → 入账并标记为「情绪消费」，AI 回一句温和吐槽
- 算了不买 → 不入账，`blockedCount + 1`、`savedMoney += 金额`，AI 回「这波省下 ¥99.00，已记进你的『省下的钱』成就（累计 ¥X）」

### 6. 理财目标池

可新增 / 删除目标（名称、目标金额、已攒金额、目标日期），支持「+ 存钱」快捷存入。

每个目标显示进度条、`¥已攒 / ¥目标`、百分比，以及：

- **月结余** = 本周期剩余 ÷ 剩余天数 × 30（≤ 0 时提示「先让结余转正」）
- **还需 n 个月** = `ceil(还差的钱 ÷ 月结余)`
- 若 `还需月数 > 距目标日月数` → 「按当前速度会晚 X 个月，建议每月多存 ¥Y」

预置目标：`iPad（¥3000，已攒 ¥800，目标 2026-12-31）`。

### 8. 进账（收入）与周期重置

**三种录入入口**：`记收入` 胶囊 → 表单（金额 / 来源 / 日期 / 备注）；聊天里说「收到生活费2000」「兼职赚了300」；截图识别。

- 收入写入 `{ type: 'income', category: '收入', source: '生活费' }`，**不计入支出统计**，但参与「收支概览」与储蓄率计算。
- 来源枚举：生活费 / 兼职 / 奖学金 / 助学金 / 红包 / 退款 / 其他；聊天识别时由 `nlp.detectIncomeSource()` 按关键词推断（「到账」单独出现时按生活费理解）。
- 看板新增「收支概览」卡：本周期 **收入 / 支出 / 结余 / 储蓄率** 四格。
  `储蓄率 = (收入 - 支出) / 收入 × 100%`，收入为 0 时显示 `—`（不会出现 NaN / Infinity）；结余为负时红色显示。
- **生活费到账追问**（大白话）：当收入 ≥ ¥300 且（来源是生活费 或 备注含 生活费/到账/打钱/给我转）时，入账后追问
  > 这笔 ¥2,000 是新的生活费到账吗？要不要从现在起重新算一个周期？（就是把预算也换成这笔钱，日均重新算一遍）

  - **[要，从现在重新算]** → `budget.cycleStart = 该笔日期`、`budget.total = 该笔金额`，立即重算并回「好，新一轮开始：¥2,000 从 10-23 用到 11-22，还有 30 天，日均 ¥66.67。」
  - **[不用，只记这一笔]** → 只留流水，提示「行，这笔只当流水记着，预算没动。」
  - 同一笔只问一次（账单上记 `askedCycle: true`），换一笔新收入会重新问。
- **周期自定义起点**：`getCycle(today, payday, cycleLen, overrideStart)` 第四参传 `'YYYY-MM-DD'`（第三参直接传日期字符串也支持）。
  起点 ≤ 今天时生效：`start = overrideStart`，`end = 起点之后的第一个发钱日 - 1 天`；起点晚于今天则回退发钱日算法。
  不传时**行为与 v1 完全一致**（发钱日推算）。设置抽屉里显示「本周期：10-23 ~ 11-22（自定义起点）」并给一个「恢复按发钱日算」按钮清掉 `cycleStart`。
- CSV 的 `bills.csv` 在末尾追加 `收支` 列（前 6 列顺序不变）。

### 9. 账单分析（导入支付宝 / 微信 / 银行 CSV）

`analysis.js`（`window.AJ.analysis`），纯函数 + UMD。顶部 `📊 账单分析` → 全屏 sheet（不是窄弹窗）。

**导入格式与解码**

| 环节 | 处理 |
| --- | --- |
| 解码 | 先 `new TextDecoder('utf-8', {fatal:true})`；抛错再试 `gbk` → `gb18030` → `big5`。每次解码后都统计 `U+FFFD` 与不可见控制字符占比，**> 30% 判「无法识别文件编码」**（否则 `TextDecoder('gbk')` 对任意二进制都不抛错，PDF / xlsx 会被硬解成一大段乱码） |
| 表头定位 | 扫描**前 30 行**，取同时含「时间类列」与「金额类列」的那一行（支付宝 / 微信导出文件顶部有多行说明） |
| 列名匹配 | 大小写 / 空格 / 括号 / 全半角归一后包含匹配：时间（交易时间 / 交易创建时间 / 记账日期 / 交易日期 / 时间 / 日期）、金额（金额 / 交易金额 / 发生额 / 本次金额 / 订单金额 / 金额(元)）、**借方列**（借方发生额 / 支出金额 / 借方金额）、**贷方列**（贷方发生额 / 收入金额 / 贷方金额）、收支（收/支 / 收支 / 交易类型 / 借贷标志 / 方向）、对方（交易对方 / 对方户名 / 商户名称 / 对方）、说明（商品说明 / 商品名称 / 商品 / 摘要 / 交易说明 / 备注 / 用途）、分类（交易分类 / 分类） |
| 说明列回退 | 一列文件里「备注」常整列为空，因此说明类列会全部收集成候选并按权重降序排列：「商品」系列权重 **96~100** 高于「备注」80，取值时**取第一个非空的那个**，避免丢掉微信账单的商品名 |
| 金额清洗 | 去掉 `¥ ￥ , " 空格`，处理 `-` 与 `( )` 负数写法 |
| 收支判定 | 收入 / 收 / 贷 → income；支出 / 支 / 借 → expense；**`不计收支` / `不计入收支` → excluded**（微信转账行的标准写法）；无该列时金额为负判 expense；单列「借方发生额 / 贷方发生额」按**命中的表头文本**判断而不是按别名常量 |
| 借贷双列 | 银行流水同时有「借方发生额」「贷方发生额」时走双列分支：借方有值 → expense、贷方有值 → income、两列都有值取绝对值较大者并标 `amountConflict`；贷方行不会再因为主金额列为空被整行跳过 |
| 转账兜底 | 见下方「转账型收入」判定表；提现 / 还款 / 借贷类无论方向一律 `excluded: true` |
| CSV 解析 | 逐字符状态机，支持字段内逗号与 `""` 转义（不用 `split(',')`）、自动识别逗号 / 制表符 / 分号 |

**「转账」类记录怎么算**（`isWithdrawOrRepay` / `isTransferText`，优先级自上而下）

| 情形 | 判定 | 例子 |
| --- | --- | --- |
| `收/支 = 不计收支 / 不计入收支` | 永远 `excluded` | 微信转账行 |
| 分类 / 交易类型含 `提现 / 还款 / 信用卡还 / 还花呗 / 投资理财 / 理财赎回 / 借贷` | 永远 `excluded`（收入方向也不算收入） | 「零钱提现」「信用卡还款」 |
| `收/支 = 收入` | **计入收入**，即使 `交易类型 = 转账`；同时标 `transferIncome: true` | 爸妈用微信转账打生活费 |
| 支出方向 + 文字含 `转账 / 转入 / 转出 / 汇款` | `excluded`（给室友转账不是消费） | 「转账给李四」 |

提现 / 还款只匹配「分类 + 交易类型」这类标签列，**不匹配对方名 / 商品名**，所以「借贷宝超市」不会因为商户名叫「借贷宝」被误杀。
转账型收入会在导入状态栏提示「其中 N 条为转账型收入，已计入；若为本人账户互转请手动排除」（`parseInfo.transferIncomeCount`），把「要不要算」交回给用户。

**分类映射**（`data.js` 的 `BILL_CATEGORY_MAP`）：`餐饮→餐饮`、`交通→交通`、`购物→购物`、`日用→购物`、`居住→居住`、`通讯→居住`、`医疗→医疗`、`教育→学习`、`娱乐→娱乐`、`人情往来→社交`、`收入→收入`、`其他→其他`；
`转账`、`还款` 默认标记 `excluded: true`（按上表优先级，**收入方向的转账例外**）。映射未命中时回退 `nlp.classify(对方 + 说明)`，仍无 → `其他`。

**去重**：同 `日期 + 金额 + 对方` 判疑似重复（跨文件与文件内都判），**默认只标记不删除**；报告第 8 节单列，勾选「排除疑似重复项重新统计」后重新出报告。

**9 节报告**（`report(rows, {month, excludeDuplicates, files})`）

1. 总览：总支出 / 总收入 / 结余 / 笔数 + 与上月对比（上月无数据标 `—`）、笔均、日均（按有记录的天数）
2. 分类占比与环比：金额、占比、笔数、笔均、与上月同类增减
3. Top 10 单笔大额
4. Top 10 高频商户（按笔数）
5. 周末 vs 工作日：笔数、合计、**日均**（金额 ÷ 该桶内有记录的天数，不是总额直接比）
6. 订阅型支出：连续 ≥3 个月「同对方 + 同金额」，标本月是否仍在扣 + 折合一年
7. 异常大额：单笔 > 该分类其余各笔笔均 ×3（该分类不足 3 笔不判）
8. 疑似重复：配对清单
9. 解析情况：每个文件的编码、表头行号、有效记录数、**前置说明行数**（表头之前的导出说明）、**无效数据行数**（表头之后解析不出的行）、列映射（借贷双列时**借方 / 贷方两列都列出**）

**消费建议**（`insights(report, budgetState)`，3~5 条，每条都带真实算出来的数字）覆盖：恩格尔 > 50%、情绪型占比 > 15%、21:00 后餐饮占比 ≥ 25%、小额（< ¥20）笔数占比 > 30%、订阅年化金额、周末 / 工作日日均 > 2 倍、某分类环比 > 30%、储蓄率 < 10%。语气克制，不下价值判断，不推荐具体产品 / 平台 / 理财。

**交互**：上传区（点击 / 拖拽 / 多选 `.csv` / `.txt`）→ 摘要 → 9 节可折叠报告（默认展开总览与分类）→ 底部 `导出 Markdown` / `把导入记录并入账本`（二次确认，明示会改变预算统计）/ `清空导入`。
**默认只分析不写账本**。分类占比用手写横向条形图，不引第三方图表库。

### 10. 截屏识别记账（三层降级）

`ocr.js`（`window.AJ.ocr`）。顶部 `📷 截屏记账` → 弹窗：选图 / 拖拽 / **Ctrl+V 粘贴** → 预览 → 开始识别 → 待确认卡。

```
1) 浏览器原生 window.TextDetector    → 本地识别，零网络
2) 云 OCR（可选，腾讯云 GeneralBasicOCR）→ 用户在设置里填 SecretId / SecretKey / Region 后才可能启用
3) 演示模式：内置 3 份示例小票         → 仅由用户显式点选（点「示例小票」），auto 模式绝不自动回落到示例
```

- **演示样例永远不会冒充识别结果**：`detect({mode:'auto'})` 在前两层都不可用时返回
  `{ok:false, source:'none', text:'', reason, tried:['native','cloud']}`，`text` 恒为空串；
  只有用户主动点「示例小票」（`mode:'demo'`）才会返回内置样例。打开弹窗时状态行就直接说明
  当前环境属于「可以离线识别 / 将用云端识别（需联网） / 当前只能用示例小票或手动录入」哪一种。
- 识别失败时的卡片给三个可操作出口：**用示例小票演示**、**配置云 OCR**（打开设置抽屉并定位到 OCR 区；
  已配置凭据时按钮文案变成「检查云 OCR 设置」）、**手动录入**（关闭弹窗、聚焦对话输入框）。
  失败文案按**实际失败的层**归因，不会一律甩锅给设备：设备没有识别能力 → 「不是你操作的问题，是这台设备缺少本地识别能力」；
  已配云 OCR 但云端请求失败 → 「云端识别没成功 —— 凭据已配置，但这次请求失败」（并提示查网络/跨域、核对凭据）；
  本地识别读出空文本 → 「可能是这张图太模糊」。
- 双保险：若结果 `source === 'demo'` 且当前存在用户上传的图片，预览图会被隐藏，结果卡顶部加黄色提示
  「⚠️ 这是内置示例，不是你上传的截图，仅用于演示流程」。
- 云 OCR 用 **Web Crypto** 实现 TC3-HMAC-SHA256 签名（`crypto.subtle.importKey / digest / sign`），不引第三方库；
  凭据单独存 `localStorage['ai_jizhang_ocr']`，设置面板明示「Key 存在本机浏览器，仅本地调用，勿在公用电脑填写」，并提供「清除凭据」。
- **未配置凭据时不会发起任何网络请求**（`ocr.js` 是全项目唯一出现 `fetch` 的文件，且只在用户主动点识别且凭据存在时执行）。
- 失败一律返回结构化结果并给出下一步（本地/云端各自的原因会拼进 `reason`），不会白屏或抛未捕获异常，`detect()` 永不 reject。
- `parseReceipt(text)` 输出 `{amount, merchant, date, payMethod, confidence, dateWarn}`：
  - 命中「实付 / 支付金额 / 合计」等标签 + 完整日期 → `high`
  - 只命中金额标签 → `medium`
  - 金额靠「取最大值」猜测 → `low`（UI 提示「识别可能不准，请核对金额」）
  - 完全无金额 → `{ok:false, reason:'未识别到金额'}`，引导手动录入
  - 解析出的日期早于「今年 − 1 年」时**保留原值但降一档置信度**，并把 `dateWarn` 显示成「识别到的日期较早，请核对」
- 3 份演示样例的日期在**访问时按当天现算**（`SAMPLES` 是 getter），不会因为写死往年日期导致「确认入账后看板支出没变化」；
  确认卡的日期输入框同时带 `min`（今天 − 365 天）与 `max`（今天）。
- 确认卡的金额 / 分类 / 备注 / 日期都可改，确认后**走既有入账与冷静期流程**（高价情绪型消费仍会被拦截）。

### 12. 省钱雷达（商家活动日历 + 比价）

「记账」管的是钱花出去之后；「省钱雷达」管的是**花出去之前**——今天哪家有活动、这个价到底贵不贵。

**入口**：顶栏 `💰 省钱` → 「省钱」面板 → 面板顶部一级分段切「🛒 省钱雷达」/「💡 省钱图谱」。
雷达与图谱共用同一个面板、各保留自己的二级页签（雷达 4 个 / 图谱 5 个）；看板 `🛒 省钱雷达` 卡片直达雷达侧，
看板 `💡 今天怎么省` 卡片直达图谱侧；简洁版走底部「省钱助手」Tab（或「我的 › 省钱助手」）再切分段。

**① 真实日期算法（不靠记忆、不靠联网）**

按《广轻大南海北区优惠日历》落地 8 个**校区真实点位**：肯德基（校门口商业街）每周四、麦当劳（阳光广场）每周一 13.9 元随心配、
瑞幸 / 库迪（阳光广场）每周二 9.9 元两杯，另有赵一鸣零食、尊特优选（第二饭堂三楼）、校内便利店（各饭堂旁）、
润泰超市（正门斜对面 150 米）、宿舍楼下小卖部 5 家常驻点位。
每家都带「地点 + 优惠内容 + 理财专家建议」，全部由 `Date.getDay()` / `datetime.weekday()` 直接算：指定任意日期都能算出「下一次是哪天、还有几天」，
不会因为模型记错、活动页改版而过期。大促（双11 / 双12 / 年货节 / 38节 / 618 / 开学季）按固定月日滚动计算。

产出两份东西：
- 面板里「14 天日历」逐日列出哪天有活动；
- 底部 **下载真实商家日历.csv**，内容由代码生成（Excel 直接打开，日期是真的，不是手抄的）。

**② 比价口径引擎（前端 `deals.js` 与后端 `deals_engine.py` 同一套规则）**

输入各平台报价（价格 / 规格 / 运费 / 券 / 需买几件），输出：

```
到手价 = 标价 × 需买件数 + 运费 − 券
折合单价 = 到手价 ÷（规格数量 × 需买件数）
```

关键判定（这些地方最容易算错、也最容易糊弄人）：
- **规格不同只能比单价**：`12 包 12.99` vs `24 包 42.23`，差的是单价不是总价；
- **「需买 N 件」不能当单件价**：`99 元 × 2 件 = 198 元`，跟单件 89 元比会说成「贵 109 元」；
- **规格口径对不上就拒绝下结论**（`mixed` / `comparable=false`）：宁可说「比不了」，不硬凑一个「最便宜」；
- 单位折算支持 ml / g / kg / 斤 / mAh / 包 / 抽 / 提 / 瓶 / 罐 / 袋（`两瓶装500ml`、`280抽6提`、`10000mAh` 都能读）。

**③ 大模型工具调用（`deals_api.py`）**

`POST /api/deals/ask` 注册了三个工具（`get_today_deals` / `get_deal_calendar` / `compare_prices`），
模型先调工具拿**真实日期和真实计算结果**，再组织语言——不是让它凭记忆说「周四有活动」。
没配 `LLM_API_KEY` 时自动降级为本地确定性回答（结论一样，只是没有自然语言润色）。

| 接口 | 作用 |
|---|---|
| `GET /api/deals/today?date=2026-10-24` | 当天活动 + 双11 倒计时 + 下一次疯狂星期四 |
| `GET /api/deals/calendar?days=14` | 未来 N 天逐日日历 |
| `GET /api/deals/calendar.csv` | 下载真实商家日历 CSV |
| `POST /api/deals/compare` | 比价（到手价 / 单价 / 可比性 / 排名 / 时机 / 预算） |
| `GET /api/deals/quote?item=充电宝&price=89&budget=100` | 这个价属于哪一档 + 该不该等大促 |
| `POST /api/deals/ask` | 大模型 tool-calling 入口 |

启动：`python deals_api.py`（默认 8010，文档 `/docs`）。

**④ 刻意不做的事（写进代码注释，也写进面板的「数据说明」）**

- **不抓电商页面**：价格会过期、抓取不合规，也不稳定；
- **不编价格**：没有真实报价时，只给「品类价格带」参考 + 明确告诉用户还差哪个平台的价；
- **不承诺最低价、不导流、不发店铺链接**。

想接真实价格？在 `.env` 配 `PRICE_API_URL` / `PRICE_API_KEY` / `PRICE_FIELD_MAP`，
把官方接口返回的字段映射进同一个比价引擎即可，计算逻辑不用改一行。

### 13. 省钱图谱（100 条动作 + 打卡省钱账）

**和省钱雷达的分工**：雷达回答「**哪天**有活动、**谁**更便宜」；图谱回答「**具体怎么操作**才省」。

但**入口和面板已经合并成一个「省钱助手」**，面板顶部用一级分段切换——省掉一个顶栏按钮，也不再有「该点哪个」的犹豫。

**入口**：顶栏「💰 省钱」统一面板（面板顶部切「省钱雷达 / 省钱图谱」）/ 看板「🛒 省钱雷达」「💡 今天怎么省」两张直达卡 / 简洁版底部「省钱」Tab 与「我的 › 省钱」（**简洁版是独立页面，不是弹窗**）/ 聊天里说
「今天怎么省」「省钱图谱」「所有省钱大全」「省钱大全」「省钱攻略 奶茶」「我的省钱账」。
（细节：看板两张卡的「查看」各自直达对应侧；雷达 4 个二级页签、图谱 5 个，切分段不会丢各自的页签。）

**两套 UI 的呈现方式不同**：完整版点顶栏「💰 省钱助手」弹出面板（遮罩 + 圆角浮层，`Esc` / 点遮罩关闭）；
简洁版底部有独立的「省钱助手」Tab（6 格：记账 / 明细 / 预算 / 省钱助手 / 理财专家 / 我的），进去是**整页区块、不是弹窗**——
同一份 `#saveHubSheet` 由 `mountShellPanels()` 搬进 `#spSaveBody`（切回完整版时再搬回遮罩），
所以没有遮罩、没有关闭按钮，靠底部 Tab 离开（不打断「雷达 / 图谱」分段的当前选择）。

**五个页签**

| 页签 | 内容 | 关键约束 |
|---|---|---|
| 今天 | 三个数字（本周期省下 / 本周期打卡 / 累计省下）+ 今日清单 + 今天已打卡（可撤销） | **今天用不了的条目绝不进清单**：周一的「周四肯德基」不许出现 |
| 图谱 | 100 条全量，搜索 + 10 分类筛选 + 每条展开 10 个字段 | 分类与搜索是**叠加**关系；搜索结果高亮关键词 |
| 大全 | **所有省钱大全**：100 条压成一行一条的速查索引（按 10 类分组） | 「一眼扫完 100 条」的场景用，不占一屏一条；点任一行跳到图谱并自动展开详情 |
| 省钱账 | 累计省下 / 总次数 / 本周期次数 + 分类条形 + 最近 12 条打卡 | 累计**不随预算周期清零**，与「本周期」分开算 |
| 说明 | 100 条从哪来、金额怎么算、三个标签含义、红线 | 面板里直接披露存储键名，用户能自己核对 |

**「大全」和「图谱」为什么都要有**：图谱是「读」的（一条占一屏、10 个字段），大全是「扫」的
（一行一条、标题 + 省多少 + 何时能用）。100 条里找自己今天能干的，先扫再读；两者共用同一份数据，
索引行点进去会带着分类与详情一起落到图谱页签，不需要用户再找一遍。

**所有省钱大全的 Markdown 导出**：大全页签工具条上一键导出 `.md`，含 100 条全量（做法 / 门槛 / 坑在哪 /
数据来源）+ 我的打卡次数，可贴进群、笔记或交给别的工具。纯前端拼字符串，不联网。

**金额怎么来的（`save.type` 四型）**

| 类型 | 含义 | 数量 | 说明 |
|---|---|---|---|
| `fixed` | 固定省额 | 1 | 原文给了明确差价 |
| `ratio` | 折扣比 | 5 | 有原价基准才乘；**缺基准返回 `null` 而不是 0**（0 会让人以为这条没用） |
| `range` | 区间取中位 | 89 | 原文只说「省几十」这类 |
| `none` | 无法量化 | 5 | 保温杯、图书馆：照样能打卡，但不进金额累计 |

**三个诚实性标签（`certainty`）**：无标签 = 规则稳定；`力度常变` = 会员日 / 百亿补贴；`以你学校为准` = 依赖具体校区门店（16 条）。

**⚠️ 大促 / 年卡型条目（`save.once`）金额记 0**

双 11 的「省 100-500」是**整场活动的总额**，不是「今天点了这一下省了多少」。
若校验时直接入库，点一次「双 11」就往省钱账里加 ¥300，累计金额瞬间失真、分类条形被促销类霸榜。
所以这类条目只计打卡次数、金额记 0，卡片上标「大促可省 / 全年可省 / 一次性省」，省钱账里也会说明有几条只计次数。

**打卡存储：独立键 `ai_jizhang_savings_v1`**

不并进 `ai_jizhang_v1` 的三个理由：

1. 主账本一动 `normalizeState()` 就要重跑全套账本回归，风险大；
2. 省钱记录损坏时**只重置自己**，绝不能让用户丢掉真实账单（坏 JSON → 清空 + 提示一次，账单不受影响）；
3. 「买对省 X」和冷静期「拦下 Y」是两个概念，合并显示会让用户以为同一笔省了两次。

记录结构 `{ id, date, saved, manual, at }`；归一化规则：非法 id / 非法日期丢弃、同 `(id,date)` 去重、
`saved` 非法按 0、总量上限 2000 条（超出丢最旧）。第二次点同一条目即撤销（幂等）。

**今日清单的硬规则（比排序更重要）**

```
① 有 trigger 但今天不命中  → 直接排除，不参与排序
② 命中今天的条目优先，受 limit（5）限制
③ 常驻条（trigger=null）只做补位，最多 3 条
排序：score ↓ → 可省金额 ↓（once 型视为 -1）→ id 字典序 ↑
```

最后一级用 `id` 字典序是为了**同日期两次渲染顺序必须完全一致**——否则「可复现」无法验收。

打分：`40 命中今天 + 25 撞本周期 Top1 分类 + 20 该分类有支出 + 15 预算紧张 + 10 力度稳定 + 5 能算出金额`。
所以「你 62% 的钱花在餐饮」会真的把餐饮类动作往前推，这是**账本联动**的落地点。

## 五、关键设计决策

1. **中文数字必须带单位或动词或位于句末两位以上**，否则 `三食堂`、`一双鞋` 会被误判成金额。
2. **金额切段代替连接词切分**：一句话里出现 N 个金额就切 N 段，天然支持「打车 15 和奶茶 12」。
3. **日期上下文继承**：「昨天打车15，奶茶12」第二笔没有时间词，继承第一笔的「昨天」。
4. **冷静期把 `want` 也算作非刚需**：需求原文的判定是「!刚需(情绪型)」，服装鞋包虽然动机记为
   「刚需 + want:true」，但从产品意图上属于冲动消费，因此一并纳入拦截，避免「¥299 的卫衣」绕过提醒。
5. **localStorage 失败降级**：读写全部 `try/catch`，失败后切内存存储并在顶部显示「当前为临时模式，关闭页面数据不保留」。
6. **周期重置用独立的 `budget.cycleStart`，不改写 `payday`**：这样「恢复按发钱日算」只要清空一个字段，
   而且 v1 的 `getCycle(today, payday)` 调用方一行都不用改（等价性用 720 组用例回归）。
7. **导入默认只分析、不写账本**：并入账本必须用户主动点击 + 二次确认，且导入时把**支出方向的**「转账 / 还款」标记为
   `excluded`，因为给室友转账、还花呗不是消费，混进支出会让所有占比失真。
   **收入方向的转账要计入**——爸妈打生活费在账单里就是「交易类型=转账」，排掉它会让收入显示 0；
   但会打 `transferIncome` 标记并在状态栏提示，把「是不是本人账户互转」交回用户判断。
8. **全项目只有 `ocr.js` 出现 `fetch`**，并且只在「用户配了云 OCR 凭据 + 主动点识别 + 有图片」三条同时成立时才执行；
   默认路径（原生识别 / 演示样例）零网络，保证断网也能演示。
9. **周末 vs 工作日比的是「日均」**：周末天数少、总额天然低，直接比总额会得出「周末更省」的错误结论，
   所以两边都除以「该桶内有记录的天数」。

## 七、已知限制

1. **周期长度固定按发钱日推算**：`getCycle` 在未传 `cycleLen` 时，结束日为「次月发钱日 - 1 天」，
   遇到 2 月等短月份时周期会短几天（这是正确的日历行为，但演示时请留意）。
2. **发钱日限制在 1-28**：避免 29/30/31 号在小月里不存在的问题。
3. **语音输入依赖浏览器**：仅 Chrome / Edge 支持 `webkitSpeechRecognition`，Safari 与 Firefox 会置灰。
4. **CSV 三连下载**：部分浏览器的「多文件下载」拦截策略可能只放行第一个文件，需要允许本站点下载多个文件。
5. **NLP 不是大模型**：基于词典与规则，能覆盖常见校园记账句式，但生僻说法（如「今天消费了一个小目标」）会走到「没听清金额」的兜底。
6. **恩格尔系数默认不预警**：演示数据的餐饮占比约 32%，属于健康区间；想现场看橙色预警，多记几笔餐饮即可。
7. **无多用户/云同步**：数据只在本机 localStorage，符合「断网可演示」的参赛要求。
8. **云 OCR 可能受浏览器跨域限制**：`file://` 或普通网页直接调腾讯云接口可能被 CORS 拦下，
   失败时会给出提示并引导使用示例小票或手动录入，不会白屏；需要稳定云识别时请用本地服务器 + 腾讯云控制台配置允许的来源。
9. **Windows 桌面 Chrome 不支持 `window.TextDetector`**：因此**不配置云 OCR 时，截屏识别只能走「示例小票」或「手动录入」**，
   上传自己的截图点「开始识别」会得到一条明确的「这台设备没有可用的文字识别能力」说明 + 三个出口按钮
   （用示例小票演示 / 配置云 OCR / 手动录入）。**应用不会拿示例数据冒充识别结果**：`auto` 模式没有任何能力时
   返回 `ok:false, source:'none', text:''`，内置样例只在用户主动点「示例小票」时出现，且届时若存在用户图片，
   预览图会被收起并显示「这是内置示例，不是你上传的截图」的黄色提示。
10. **导入账单默认不入账本**：只有点「把导入记录并入账本」并二次确认后才写入，且并入后会立即改变预算统计与日均。
11. **GBK 解码依赖浏览器 `TextDecoder('gbk')`**：Chrome / Edge 支持；Safari 部分版本不支持，会落到「无法识别文件编码」，
    可以把文件另存为 UTF-8 再导入。
12. **截图识别不是万能**：菜单、聊天记录、严重模糊的截图可能读不到金额；此时会用结构化错误提示并给手动录入入口。
13. **导入不自动去重写入**：疑似重复默认只标记，重复并入同一份文件会产生重复账单。
14. **省钱图谱的金额是估算区间，不是报价**：知识库里只有「省 30%」「省几十」这类说法，
    `range` 型取区间中位、`ratio` 型必须有原价基准才算，`none` 型直接不计金额。
    界面上从不说「最低价」，也不写死任何平台的实时价格；真下单前以商家当期页面为准。
15. **大促 / 年卡型条目只计打卡次数、不计金额**（`save.once`）：双 11 的「省 100-500」是整场活动的总额，
    记进省钱账会让累计虚高，所以金额记 0，卡片上标「大促可省 / 全年可省 / 一次性省」。
16. **省钱打卡的金额可以事后手改，但只有一个「覆盖」口径**：省钱账每条记录右侧有「改」，
    填 0~10000 之间的数即覆盖估算，`manual` 记为 `true`（导出 CSV 时「是否手动改过」列写「是」）；
    **清空输入框 = 恢复引擎估算**，`manual` 回到 `false`。这里不保留历史修改记录，也不做多次改动的审计。
17. **活动日期由本地日期算法推算**（周几 / 每月几号 / 固定月日 / 时间区间），不联网抓取，所以离线可用，
    但**商家临时改档期不会自动同步**——这也是多数条目带「力度常变 / 以你学校为准」标签的原因。
18. **深色主题的页签选中态单独补过一条规则**：`[data-theme="dark"] .atab` 的权重高于 `.atab.active`，
    会把选中页签刷成和未选中同色（账单分析 / 省钱雷达 / 省钱图谱三处都受影响）。已补
    `[data-theme="dark"] .atab.active`，改这组样式时别把这条删掉。
19. **窄屏顶栏做了两级收口**：≤520px 缩小控件间距，≤430px 把「记一笔」收成图标、品牌只留 logo。
    原因是 8 个控件实测需 372px，而 390px 视口的可用宽只有 366px——不收口会把设置齿轮挤出屏幕。
20. **视频教学的两个 B 站链接走第三方镜像站**（`snm0516.aisee.tv`，内容源为公开 B 站视频）：
    镜像域名/路径可能变动或限流，**答辩前请先实测能否播放**，并准备本地下载版本兜底；
    卡片内已写明来源与「镜像不可用时在 B 站搜索同名标题」，不宣称是 B 站官方链接。
    红米鸡只有博主名、没有公开主页链接，因此是复制指令而**不是**超链接，避免做成失效的假链接。
    复制功能优先 `navigator.clipboard`，非 https / file:// 下自动降级 `execCommand`；两者都失败时提示手动记下。
21. **2 位 B 站省钱博主的主页是第三方站点**：`m.bilibili.com/space/<uid>` 会 302 跳到
    `space.bilibili.com/<uid>`，属正常跳转，不影响使用；B 站可能要求登录、或对部分内容做地区 / 年龄限制，
    打不开时在 B 站 App 内搜博主名即可。**不要**把链接改成 `www.bilibili.com/space/<uid>`——该形式会 404。
    天月遥、先天省钱圣体均为 `m.` 形式（302 后的 `space.` 与 `m.` 指向同一 UID），不要自行改写。
    博主的观点不代表本应用立场，卡片 `resNote` 已声明「不构成投资建议」；主页更新频率高，卡片只保证链接有效、不保证每条视频仍可看。
